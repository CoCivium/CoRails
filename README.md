# CoRails

CoRails is a bounded repository surface for invariants, guardrails, rules, challengeable safety rails, and their supporting ledgers, generated projections, receipts, and tests.

## CoRails+ evolution intake

CoRails participates in the shared [CoAll GitHub Evolution Fabric](https://github.com/CoCivium/CoCivium/blob/main/docs/Evolution/COALL_GITHUB_EVOLUTION_FABRIC_R0.md).

Capable sessions may contribute bounded candidate rails when they reduce ambiguity, collision risk, replay, authority drift, privacy/public risk, or human-attention debt.

Prefer typed relations with source refs, scope, epistemic class, contradiction/challenge path, testability where possible, and explicit supersession rather than silent replacement.

A rail in this repository is not automatically universal, current, canonical, runtime-enforced, scientifically validated, or authoritative merely because it is stored or merged here.

## Repository surfaces

- `rules/` — candidate and adopted repo-local rule projections;
- `ledger/` — lineage, history, supersession, and currentness evidence;
- `generated/` — derived projections that should remain reproducible from stronger source state where possible;
- `receipts/` — bounded evidence of repository-local transitions;
- `scripts/` — tooling related to rail inspection, generation, and validation;
- `INBOX/` — provisional intake; presence does not imply acceptance.

## Contribution posture

Before mutating:

1. refresh current head;
2. search for an existing equivalent or stronger rail;
3. bind source/provenance;
4. identify scope and collision domain;
5. classify confidentiality and effect;
6. prefer branch/PR for uncertain or cross-cutting changes;
7. preserve superseded history;
8. do not infer global authority from repository write access.

Useful rails:

`RAIL_NE_CANON`  
`RULE_TEXT_NE_RUNTIME_ENFORCEMENT`  
`REPOSITORY_NE_ONTOLOGY`

`CHALLENGE_PATH_BEATS_SILENT_CERTAINTY`
